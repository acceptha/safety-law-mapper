# data/incidents — KOSHA 사고속보 수집 데이터

## 출처

**안전보건공단 산업안전포털 사고속보**
<https://portal.kosha.or.kr/business-apply-search/etc-biz/acc-invest-act/cont2>

수집 방식과 설계 근거는 [사고속보 연계 기획서](../../docs/사고속보-연계-기획서.md)를 참조하세요.

## 이 디렉터리가 다루는 것 / 다루지 않는 것

- ✅ **적용 법령** — 해당 작업 유형에 적용되는 조항
- ❌ **위반 판정 아님** — 사고속보는 조사 전 신고 단계 정보이며, 원문에도 *"조사결과에 따라 변경될 수 있습니다"*라고 명시돼 있습니다. 특정 사업장의 법령 위반을 뜻하지 않습니다.
- ❌ **개인정보 없음** — 원문에 재해자 식별정보가 없습니다(사망자 수만 기재). 원문 형식이 바뀌어 개인정보가 포함되면 수집을 중단합니다.

## 저작권 — 제목 저장에 관한 판단

안전보건공단 [저작권정책](https://kosha.or.kr/copyright-policy)은 **공공누리(KOGL) 표시가 부착된 저작물에 한해** 자유이용을 허용합니다. 사고속보 게시물에는 **공공누리 표시가 없습니다**(2026-08-28 확인). 따라서 자동으로 자유이용 대상이 되지는 않습니다.

현재 기본 설정은 **제목(`title`)을 저장**합니다. 근거:

1. 저작권법 제7조제5호는 *"사실의 전달에 불과한 시사보도"*를 보호 대상에서 제외하며, 사고속보 제목은 `[날짜, 지역] 사고 사실` 형식의 사실 기술입니다.
2. 나머지 필드(날짜·지역·사고유형·사망자 수)는 사실 자체로 저작물성이 없고, `work_keywords`는 이 저장소의 자체 어휘(렉시콘·매핑 키워드)에서만 나옵니다 — 원문 표현을 그대로 담지 않습니다.
3. 제목이 없으면 공백 군집 분석(이 파이프라인의 주 목적)이 사실상 불가능합니다.

**보수적으로 운영하려면** 제목 없이 수집하면 됩니다:

```bash
python scripts/fetch_kosha_incidents.py --no-store-titles
```

이 경우에도 구조화 필드와 원문 링크는 그대로 유지되므로 매핑·커버리지 집계는 동일하게 동작합니다.

출처 표시는 어느 쪽이든 필수로 유지합니다.

## 갱신

```bash
python scripts/fetch_kosha_incidents.py            # 최신 2페이지 증분 수집
python scripts/fetch_kosha_incidents.py --pages 25 # 백필
slm incidents --gaps                                # 미매핑 = 매핑 기여 대상
```

게시가 부정기(사고일 기준 3~8일 지연)이므로 하루 1회 이상 수집할 실익이 없습니다.
