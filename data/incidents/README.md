# data/incidents — KOSHA 사고속보 수집 데이터

## 출처

**안전보건공단 산업안전포털 사고속보**
<https://portal.kosha.or.kr/business-apply-search/etc-biz/acc-invest-act/cont2>

수집 방식과 설계 근거는 [사고속보 연계 기획서](../../docs/사고속보-연계-기획서.md)를 참조하세요.

## 이 디렉터리가 다루는 것 / 다루지 않는 것

- ✅ **적용 법령** — 해당 작업 유형에 적용되는 조항
- ❌ **위반 판정 아님** — 사고속보는 조사 전 신고 단계 정보이며, 원문에도 *"조사결과에 따라 변경될 수 있습니다"*라고 명시돼 있습니다. 특정 사업장의 법령 위반을 뜻하지 않습니다.
- ❌ **개인정보 없음** — 원문에 재해자 식별정보가 없습니다(사망자 수만 기재). 원문 형식이 바뀌어 개인정보가 포함되면 수집을 중단합니다.

## 저작권 — 제목 저장에 관한 판단

안전보건공단 [저작권정책](https://kosha.or.kr/copyright-policy)은 **공공누리(KOGL) 표시가 부착된 저작물에 한해** 자유이용을 허용합니다. 사고속보 게시물에는 **공공누리 표시가 없습니다**(2026-08-28 확인). 따라서 자동으로 자유이용 대상이 되지는 않습니다.

현재 기본 설정은 **제목(`title`)을 저장**합니다. 근거:

1. 저작권법 제7조제5호는 *"사실의 전달에 불과한 시사보도"*를 보호 대상에서 제외하며, 사고속보 제목은 `[날짜, 지역] 사고 사실` 형식의 사실 기술입니다.
2. 나머지 필드(날짜·지역·사고유형·사망자 수)는 사실 자체로 저작물성이 없고, `work_keywords`는 이 저장소의 자체 어휘(렉시콘·매핑 키워드)에서만 나옵니다 — 원문 표현을 그대로 담지 않습니다.
3. 제목이 없으면 공백 군집 분석(이 파이프라인의 주 목적)이 사실상 불가능합니다.

**보수적으로 운영하려면** 제목 없이 수집하면 됩니다:

```bash
python scripts/fetch_kosha_incidents.py --no-store-titles
```

이 경우에도 구조화 필드와 원문 링크는 그대로 유지되므로 매핑·커버리지 집계는 동일하게 동작합니다.

출처 표시는 어느 쪽이든 필수로 유지합니다.

## 갱신

**자동 수집**: `.github/workflows/incidents.yml`이 매일 07:00 KST에 실행합니다. 수집할 게 없는 날은 커밋하지 않고 조용히 끝납니다.

**알림**: 수집 직후 두 갈래로 나갑니다. 두 신호의 빈도가 16배 달라 하나로 묶을 수 없습니다 — 근거는 [기획서 §7.21](../../docs/사고속보-연계-기획서.md).

| | 언제 | 어디로 | 측정값 |
|---|---|---|---|
| **공백** | 그날 수집분에 미매핑이 있으면 즉시 | 새 이슈 (`data-gap`) | 주 0.32회, 100%가 손댈 것 |
| **요약** | **8건 또는 7일 중 먼저** | 요약 이슈에 댓글 (`digest`) | 주 0.76회, 1회당 7.6건 |

새 사고마다 알리지 않는 것은 의도한 것입니다. 사고는 주 5.9건 들어오지만 대부분은 이미 맞는 조문으로 갑니다 — 수집될 때마다 알리면 주 1.96회 울리고 **그중 16%만 손댈 것이 있습니다.** 두 주면 아무도 보지 않게 되고, 그러면 정작 필요한 날의 알림까지 같이 묻힙니다.

순수 개수 임계값은 쓰지 않았습니다. 게시가 몰려 있어 조용한 구간에서는 8건이 차는 데 3주가 걸립니다(최악 20일). 일수 상한이 그걸 끊습니다.

본문에는 저장소 소유자 멘션이 들어갑니다. **봇이 만든 이슈는 멘션 없이는 알림이 가지 않습니다** — 기본 알림 설정이 '참여 중이거나 멘션된 것'이기 때문입니다.

```bash
python scripts/report_new_gaps.py                      # 오늘 수집분의 공백 (없으면 출력 없음)
python scripts/report_new_gaps.py --date 2026-10-09    # 특정 수집일로 확인
python scripts/report_new_incidents.py --since 2026-10-12  # 묶음 요약 (보낼 때 아니면 출력 없음)
python scripts/simulate_alert_policies.py              # 알림 주기 소급 측정
```

수동 실행:

```bash
python scripts/fetch_kosha_incidents.py            # 증분 수집 (신규 없는 첫 페이지에서 정지)
python scripts/fetch_kosha_incidents.py --pages 250 # 전체 백필
python scripts/fetch_kosha_incidents.py --reprocess  # 렉시콘 수정 후 오프라인 재생성
python scripts/build_coverage_report.py              # docs/incidents/coverage.md 갱신
slm incidents --gaps                                 # 미매핑 = 매핑 기여 대상
```

게시가 부정기(사고일 기준 3~8일 지연)이므로 하루 1회 이상 수집할 실익이 없습니다.

커버리지 현황과 공백 큐는 [coverage.md](../../docs/incidents/coverage.md)에서 볼 수 있습니다.
