# MCP grounding 실측 — 도구 유무에 따른 인용 검증가능성 비교

`slm-mcp`가 실제로 무엇을 바꾸는지 측정한 기록입니다. 주장 대신 숫자를 남깁니다.

> **표본 1건입니다.** 벤치마크가 아니라 메커니즘 시연이며, 이 수치를 일반화해서는 안 됩니다.

## 방법

| 항목 | 내용 |
|---|---|
| 측정일 | 2026-10-08 |
| 질문 | "밀폐공간에서 용접 작업을 할 때 사업주가 지켜야 하는 산업안전보건기준에 관한 규칙상의 의무를 알려주세요. 반드시 해당 조항 번호(제○○조)와 조문 제목을 함께 명시해 주세요." |
| BEFORE | 중립 디렉터리, `--strict-mcp-config` + 빈 MCP 설정, `--allowed-tools ""` — 도구·파일·웹 접근 전면 차단 |
| AFTER | 동일 질문, `slm-mcp`만 연결 (`search_laws` / `get_mapping` / `list_categories`) |
| 채점 | 답변이 인용한 조항 번호를 추출해 **측정 시점(2026-10-08) 본 저장소가 보유한 검증된 조항 104건**과 대조 (링크 URL 내 조항은 제외). 데이터는 이후에도 늘어나므로, 이 분모는 측정일 기준으로 고정해 읽어야 합니다. |

재현:

```bash
claude -p "<질문>" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --allowed-tools ""   # BEFORE
claude -p "<질문>" --strict-mcp-config --mcp-config mcp.json \
  --allowed-tools "mcp__slm__search_laws" "mcp__slm__get_mapping" "mcp__slm__list_categories"  # AFTER
```

## 결과

| 지표 | BEFORE (도구 없음) | AFTER (MCP 연결) |
|---|---|---|
| 인용한 조항 수 | 19 | 10 |
| 검증 데이터에 존재 | 8 (**42%**) | 10 (**100%**) |
| 검증 불가 (데이터 밖) | 11 (**58%**) | 0 |
| 도구가 이 질의에 반환한 범위 밖 | 11 | **0** |
| 제목 일치 (검증 가능분 중) | 7 / 8 | **10 / 10** |
| 원문 링크 제시 | 없음 | 전건 law.go.kr |
| 검증일 명시 | 없음 | 있음 (2026-08-26~27) |

BEFORE에서 검증할 수 없었던 조항:

```
제621조, 제622조, 제624조, 제625조, 제638조, 제639조,
제641조, 제643조, 제306조, 제630조, 제631조
```

## 해석 — 과장하지 않기

### 모델은 뻔뻔하게 지어내지 않았다

BEFORE 답변은 스스로 이렇게 밝히고 시작했습니다.

> "아래 조항 번호와 제목은 제가 기억하고 있는 내용입니다. 이번 답변을 위해 원문을 다시 확인하지는 않았습니다. (…) 국가법령정보센터에서 최신 조문을 꼭 확인하세요."

요즘 모델은 근거가 없을 때 침묵하는 대신 **고지하고 답합니다.** "LLM은 법을 지어낸다"는 단순한 서사는 이 실측과 맞지 않습니다.

### 그래서 문제가 없는 것은 아니다

검증 불가 11건은 **허위라는 뜻이 아닙니다.** 측정 시점 본 저장소가 보유한 104개 조항 밖이라 이 데이터로는 진위를 가릴 수 없다는 뜻이고, 실제로 상당수는 존재하는 조항일 가능성이 높습니다.

핵심은 다릅니다.

> **답변을 읽는 사람은 19건 중 어느 것이 정확하고 어느 것이 기억에 의존한 것인지 구분할 수 없습니다.**

고지문은 책임을 이전할 뿐 검증 비용을 없애지 못합니다. 영세 사업장 안전관리자가 조항 19개를 일일이 law.go.kr에서 대조해야 한다면, 애초에 이 도구가 풀려던 문제가 그대로 남습니다.

### 실제로 틀린 부분은 제목이었다

검증 가능한 8건 중 1건에서 제목이 어긋났습니다.

| | 제619조의2 |
|---|---|
| BEFORE | 산소 및 유해가스 농도의 측정 |
| 원문 | 산소 및 유해가스 농도의 측정 및 **기록 등** |

사소해 보이지만 **"기록"은 별도의 법적 의무**입니다. 측정만 하고 기록하지 않으면 위반입니다. 조항 번호가 맞아도 의무의 범위가 좁게 전달되는, 눈에 잘 띄지 않는 종류의 오류입니다.

> **덧붙임(2026-10-14).** 같은 누락이 우리 데이터에도 있었습니다. `confined-space-work`의 제619조의2 요약은 "작업 시작 전 및 작업 중 산소·유해가스 농도 측정, 적정공기 유지 확인"이었고, 제목에 있는 **기록·3년 보존 의무가 빠져** 있었습니다. 모델의 오류를 지적한 바로 그 문장이 우리 쪽에서도 참이었던 셈입니다. 밀폐공간 구조 조문을 추가하면서 함께 고쳤습니다.

### AFTER가 바꾼 것

AFTER는 조항을 **더 적게** 인용했습니다(19 → 10). 더 똑똑해져서가 아니라, 데이터가 보증하는 범위 밖으로 나가지 않았기 때문입니다. 모르는 것을 말하지 않는 것이 이 설계의 목적입니다.

대신 인용한 10건은 전부 다음을 갖췄습니다.

- law.go.kr 원문 링크
- 사람이 원문 대조한 날짜
- 요약이 조문 전체가 아니라는 고지

AFTER 답변이 직접 쓴 문장입니다.

> "표의 의무 내용은 도구가 준 요약이라 조문 전체가 아닙니다. 세부 항목과 적용 조건은 원문으로 확인하세요."

## 한계

- **AFTER의 100%는 상당 부분 설계가 보장하는 값입니다.** 모델이 도구가 돌려준 것만 인용하고 도구가 검증된
  데이터만 돌려준다면, 100%는 측정으로 알아낸 사실이 아니라 구조상 따라 나오는 값입니다. 이 숫자를 성능 지표로
  읽어서는 안 됩니다.
  이 측정에서 **자명하지 않았던 것은 따로 있습니다** — 모델이 도구 결과에 자기가 기억하는 조항을 섞어 넣을
  수 있었지만 그러지 않았다는 점입니다. 위 표의 `도구가 이 질의에 반환한 범위 밖 11 → 0`이 그 결과이고,
  이것은 사전에 보장된 바가 없었습니다.
- **표본 1건, 질문 1개.** 다른 작업 유형·다른 모델에서는 결과가 다를 수 있습니다.
- 커버리지가 정확성을 제한합니다. AFTER가 10건만 인용한 것은 **데이터에 10건뿐이기 때문**이며, 누락된 의무가 있을 수 있습니다. 매핑 공백은 [good first issue](https://github.com/acceptha/safety-law-mapper/issues)로 열려 있습니다.
- 조항의 **해석 정확성**은 측정하지 않았습니다. 인용의 검증가능성만 봤습니다.
